SDK · Embedding

Configure an embed, and watch it change

Everything on the left is host configuration. Change it and the editor on the right becomes the thing you configured: a readonly container has reading chrome and no editing ribbon, a preview container is offered none of the 19 regions at all, a withheld capability is gone from the API as well as from the buttons, and a brand colour lands on the running editor. The snippet at the bottom reproduces whatever is on screen, so you can paste it into your own page and get the same result.

Nothing here is gated. ONLYOFFICE puts host customization behind a licence check in code — LayoutManager._applyCustomization returns early when !_licensed — so an integrator ships their chrome and then discovers the modal. This is Apache-2.0, the permissive licence is the whole point of the project, and gating the one thing that makes it worth embedding would surrender it.

Capabilities

All 9 are withheld independently: “comments only, everything else off” is a configuration, not a rung on a ladder. A list can only narrow a role, so a capability the role never granted is shown struck through and disabled — one direction to audit.

  • Start a blank document.
  • Write the document back out.
  • Export to a file the visitor keeps.
  • Open the browser's print dialog.

Chrome regions

19 whole presentations a host can decline, 8 of them ribbon bands. A region is not a capability: withholding one is a decision about your page, withholding a capability is a permission. Dropping ribbon drops every band with it.

  • Our name and mark in the top bar.
  • The document name, and renaming it.
  • The application menu bar — one of the two navigation axes.
  • The whole tabbed ribbon, strip and bands together.
  • The File page: open, save, export, print, properties, settings.
  • Character and paragraph formatting, styles, clipboard, undo.
  • Tables, pictures, shapes, links, comments, headers, symbols.
  • Page setup, margins, columns, spacing, watermark, arrange.
  • Captions, cross-references, contents, footnotes, fields.
  • Tracked changes, comments, proofing, the review mode control.
  • Outline, zoom, page setup, showing changes.
  • The contextual table band, present when the caret is in a table.
  • The left navigation rail: outline and page thumbnails.
  • The version-history timeline, its ribbon entry and its preview bar.
  • The status bar: counts, page number, language, mode.
  • The zoom cluster in the status bar.
  • The find and replace card.
  • The floating toolbar above a selection.
  • The settings dialog and the gear that opens it.

    The editor holds a WebAssembly instance of roughly 100 MB, so it boots when you ask rather than on arrival. The readout above is already live: it is resolved from the same authority the editor resolves.

    The configuration this produces

    Both panels are rewritten on every change, and between them they are the whole of what a host writes. The element takes 3 attributes; the per-capability and per-region lists travel in editor-src, because the editor resolves them before the frame's first navigation and a configuration channel that arrives after the document is on screen would be a permission granted too late. The URL parameters are autosave mode can chrome.

    The embed — paste this into your page
    webapp/brand.json — then run node webapp/tools/build-brand.mjs

    A colour that fails WCAG AA is refused by that command, naming the pair, the measured ratio, the floor and the nearest value on the same hue that would pass — not corrected, because a product shipped in an accent nobody approved is a lie a host discovers from a screenshot, and not warned about, because a warning in a build log is ONLYOFFICE's nag-modal in a different font. The floors are WCAG's own split: 4.5:1 for text, 3:1 for edges and icons. The refusal beside the Brand controls is produced by the same code that command runs, in this page, so it cannot describe a message the generator no longer emits.

    What this page does not do yet

    • Role, capability and region changes remount the frame. They are resolved before the first paint on purpose, so there is no way to apply one to a running editor without reloading it — and a channel that could would be a window in which the editor was something else. The brand controls do apply live, because a palette is a stylesheet.
    • can and chrome have no attribute of their own. The element reads 3 attributes and they are not among them, so the lists ride in editor-src's query. That works and is what the snippet above generates; an attribute apiece would read better and belongs to the element and its published types rather than to this page.
    • The brand preview is this page applying the generated stylesheet to the frame. A real white-labelled deployment commits what build-brand.mjs writes and serves it; nothing here can write a file. The CSS in the panel above is the generator's own output, byte for byte.
    • Two strips survive a container that was offered no region, and this page is how they were found. In preview the top bar still carries the document-state chip, the import-findings count and the Properties button, and the Viewing banner still offers “Switch to editing” — which a preview container can never do. Neither belongs to any of the 19 regions, so neither can be withheld; deciding where they belong is a change to the region set rather than to this page, and it is filed rather than quietly patched.
    • One document, and no host commands. The frame opens the shipped sample. For driving the editor over both transports — in-process and postMessage — with every command the registry offers, the two-panel host demo is embed.html.

    The reference for all of it is Embed the editor: the capability table, the region table, the host contract, the refusal codes, and the tests that hold each claim up.
