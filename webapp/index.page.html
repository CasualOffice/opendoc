Why OpenDoc

A document runtime, not a web-editor wrapper.

The document itself is the source of truth. The canvas is a rendering surface; UI, storage, authentication, and network policy stay yours.

01

Own the document model

DOCX parses into a typed, editable model instead of being flattened into browser markup.

  • Semantic import and export
  • Byte-identical save of unedited packages
  • Unsupported data retained or reported
02

Deterministic layout

One Rust pipeline shapes, paginates, hit-tests, and renders across every host.

  • Engine-owned caret and selection geometry
  • Tables, sections, columns, floats, math
  • Backend-neutral display list
03

Bring your own product

Every edit routes through a closed command set with undo. Everything around it is yours.

  • No mandatory UI framework
  • No required cloud service
  • Browser, native, and headless targets
Architecture

One engine. Clear boundaries.

Document semantics live inside OpenDoc. Product policy lives inside your host. That line is the whole design, so it is drawn rather than described.

  3. Open a real DOCXIn the browser editor, or embed the runtime.
quickstart 
$ git clone https://github.com/CasualOffice/opendoc.git
$ cd opendoc
$ cargo test --workspace --all-features --locked

# run the browser editor locally
$ ./webapp/build.sh
$ ./webapp/serve.py
import init, { open } from "./pkg/casual_doc_wasm.js";

await init();
const doc = open(new Uint8Array(await file.arrayBuffer()));

// a page-local point (twips, page 1) → a model anchor
const at = doc.hitTest(1, 1440, 1440);
doc.insertText(at.node, at.offset, "Hello from OpenDoc");

const rgba = doc.renderPage(0, 96);  // RGBA8888, page 0 at 96 dpi
const docx = doc.exportDocx();          // bytes, ready to save
Delivery

Where it is, and where it is going.

Shipped, active, and planned are kept separate, so a pre-release reads as a status rather than a promise.

Semantic import and export, and byte-identical save of unedited packages.

Shipped

Paragraphs, tables, sections and columns, floats with text wrap, and math.

In progress

Editing to Word parity

Comments, tracked changes, and every editing surface held to the Word and Docs standard.

Planned
