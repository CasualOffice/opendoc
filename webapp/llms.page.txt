> OpenDoc is an Apache-2.0 alternative to ONLYOFFICE Docs for documents and
> document collaboration: an embeddable, local-first editor for Word documents,
> and the deterministic Rust engine underneath it, running natively, headless,
> or in the browser as WebAssembly.

OpenDoc is developed by CasualOffice and licensed under Apache-2.0, with no
commercial edition and no licence-gated customisation. The engine, not the
browser DOM, owns document state and layout. Nothing has to run behind the
editor: it opens, edits and saves a document entirely in the browser tab. Host
applications own storage, network, authentication, fonts and product UI policy.
No server, React dependency or collaboration provider is required.

OpenDoc is pre-release. There is no stable public SDK, no tagged release, and
no published npm package or crate yet. It is not a pixel-perfect replacement for
Microsoft Word; per-construct fidelity is graded on the fidelity page below,
and those grades are hand-checked rather than CI-enforced.

## What it does today

- Formats in the browser editor. Open and save: DOCX, ODT, plain text, and a
  normalized JSON snapshot. Open only: RTF (import; there is no RTF writer).
  Export only: PDF with real, selectable text (no tagged PDF, PDF/A or
  clickable links yet), HTML, Markdown, and DOTX. Macro-enabled .docm files are
  refused at open.
- Loss reporting: an import says what it mapped, what it kept verbatim and what
  it lost, and an unedited DOCX can be written back byte-identical.
- Review: comments with replies and resolve; tracked changes with Editing,
  Suggesting and Viewing modes and accept/reject; version history kept locally
  in the browser; Compare shown as an on-page redline.
- Real-time collaboration, experimental: operational-transformation co-editing
  through an optional relay (`opendoc-relay`) that orders and forwards changes
  and never holds the document. Rooms carry a role (viewer, commenter,
  suggester, editor, owner). Remote carets and selections are shown, labelled by
  participant number. Share needs a host-supplied storage provider; the public
  demo has none, so it cannot co-edit or share. The relay has no built-in TLS,
  authentication or rate limiting, and its container image is built locally,
  not published.
- Embedding: a framework-free `<opendoc-editor>` custom element and an iframe
  mount, a capability contract the host decides, an in-page and a cross-origin
  postMessage command surface, and white-labelling from one configuration file.
  The package is buildable from the repository; it is not on npm.
- Phone layout and touch selection in mobile browsers, tested in emulation; not
  yet verified on real devices.

## Technical scope

- OOXML package admission with explicit path, size, expansion, and resource bounds.
- Normalized editable document model with styles, sections, tables, drawings,
  charts, links, fields, notes, headers/footers, comments, revisions,
  bookmarks, and content controls.
- Semantic DOCX writer plus byte-identical reconstruction for unedited packages;
  ODT import and export; RTF import.
- Rust text shaping, pagination, display-list composition, CPU raster rendering,
  real-text PDF export from the same display list, hit testing, model-anchored
  selection, command-based editing, and undo/redo.
- Rust-native, wasm32, and headless execution targets with host-populated font
  and resource seams.
